# Token Calculation and Compounding Analysis

When designing and operating agentic workflows, understanding how tokens compound across multiple turns is critical for both cost management and latency optimization. TracerLensAi employs a mathematical model to accurately project token usage based on execution traces.

## The Compounding Formula

The core of the token calculation engine (located in `src/observability/workflow_optimizer.py`) relies on the following compounding formula:

```
E_total ≈ N · P + N(N−1)/2 · (O_avg + T_avg)
```

Where the variables are defined as follows:

- **`E_total`**: The Estimated Total Tokens for the workflow.
- **`N`**: The expected or inferred number of agent loops (`loop_count`).
- **`P`**: The base prompt tokens (`base_prompt_tokens`), representing the size of the initial user prompt and system instructions.
- **`O_avg`**: The average tokens generated by the LLM per turn (`average_model_output_tokens`).
- **`T_avg`**: The average tokens returned by external tools per turn (`average_tool_output_tokens`).

### Why Does it Compound?

In an agentic loop, the LLM doesn't just read the base prompt and tools once. Every time the agent makes a decision, calls a tool, and receives a response, that entire interaction (the model's output `O_avg` and the tool's response `T_avg`) is appended to the conversational history.

In the subsequent loop, the LLM must process the base prompt _plus_ the history of loop 1. In loop 3, it processes the base prompt _plus_ the history of loop 1 _and_ loop 2. This creates an arithmetic progression of context size, which is represented mathematically by the `N(N−1)/2` triangular number formula.

## Breakdown of Metrics

The optimizer breaks down the calculation into several distinct metrics:

### 1. Compounding History Tokens

This represents the sheer volume of "history" that gets re-read across all loops.

```python
compounding_history_tokens = (N * (N - 1) / 2) * (O_avg + T_avg)
```

### 2. Estimated Input Tokens

The total number of tokens sent _to_ the model across all loops. This includes the base prompt read `N` times, plus the compounding history.

```python
estimated_input_tokens = (N * P) + compounding_history_tokens
```

### 3. Estimated Output Tokens

The total number of tokens generated _by_ the model. Output tokens do not compound in the same way, as they are generated fresh each loop.

```python
estimated_output_tokens = N * O_avg
```

### 4. Total Tokens

The final sum of input and output tokens.

```python
estimated_total_tokens = estimated_input_tokens + estimated_output_tokens
```

## Risk Level and Efficiency

Based on these projections, the engine evaluates the **Risk Level** of the workflow. High risk occurs when `N` is large or when `T_avg` (tool outputs like massive database queries) inflates the compounding history, leading to exponential cost spikes and potential context window exhaustion.

The **Cost Multiplier** is also calculated by dividing `estimated_total_tokens` by the base prompt tokens `P`. A high multiplier indicates that the multi-turn agentic nature of the workflow is significantly more expensive than a zero-shot prompt.
